The original system is configured in a star topology, where LoPy 4 micro-controllers are placed in containers, and a Raspberry Pi 4 based gateway is somewhere in the middle to communicate with the sensors through LoRa. The gateways are connected to the internet, and can be communicated with using a Chirpstack server. The goal of the project was to enable updates to the sensors over the air through the unreliable LoRa connection. That is why Linear Network Coding was investigated as a retransmission strategy.

The project itself was split into three main tasks:

  • Understanding the Chirpstack server and setting it up to work with the gateway Raspberry Pi
  • Implementing a simple LoRa communication system between the gateway and some LoPy 4 micro-controllers
  • Writing the encoder and decoder that would be used to implement Random Linear Network Coding

    Linear Network Coding

    Transmission using LoRa can be unreliable with a good amount of packet loss. TCP usually handles packet loss by retransmitting lost packets, however data transmission is costly in battery drived interet of things (IoT) devices. Usually the different IoT devices lose different packets, and retransmitting all lost packets will lead to a lot of redundancy and wasted energy.

    Linear Network Coding is a way to mitigate this. Instead of retransmitting lost packets, the sender sends a linear combination of the packets that were lost. The receiver can then use this linear combination to recover the lost packets. Let us take an example where three packets are sent and node 1 lost the first, node 2 lost the second and node 3 lost the third packet. Resending all three packets alone would require three transmissions, but send the linear combination P1 ⊕ P2 ⊕ P3 = P123 where ⊕ denotes XOR. Once the three nodes receive packet P123 they can use it to recover their lost packets by doing
    P123 ⊕ P2 ⊕ P3 = P1
    P123 ⊕ P1 ⊕ P3 = P2
    P123 ⊕ P1 ⊕ P2 = P3
    respectively. This is possible due to two properties of XOR:

  • A ⊕ A = 0
  • A ⊕ B ⊕ A = B ⊕ A ⊕ A = B
    • Now imagine hundreds of packets, with tens of them getting lost at a time. Using linear coding can reduce the amount of retransmissions significantly. Furthermore, since these are essentially systems of linear equations, they can be represented using matrices and solved using linear algebra. Which computers are very good at: [ c11 c12 ⋯ c1m c21 c22 ⋯ c2m ⋮ ⋮ ⋱ ⋮ cn1 cn2 ⋯ cnm ] [ P1 P2 ⋮ Pm ] = [ C1 C2 ⋮ Cn ] Where c are coefficients with values of either 0 or 1, and C represent coded packets that are sent forward. It is expected to send the coded packet with its corresponding coefficients row. Therefore, it is important to strike a balance between number of packets to code together and the overall size of one packet. That's why a group of packet is lumped into a generation, and only packets in the same generation is coded together.

    Once a node receives a coded packet it reduces it using the packets it already has received, while making sure to update the received coefficients row with the reductions. The output will either be a row of zeroes, meaning no new information is in this packet, a row with only one coefficient, meaning a new packet was calculated, or a row with more than one coefficient, meaning this row includes new information, but not enough packets have been received to decode it. Once the node has received all the packets in a generation it sends a message back asking for a new generation.

    Random Linear Network Coding

    While receiving feedback from the nodes can help in constructing less redundat coded packets. It is usually not the best idea, as transmitting data is requires more energy than receiving data. Therefore, it is important to also reduce the number of feedback messages from the noeds. Random Linear Network Coding tries to tackle this by simply sending random combinations of the packets in a generation until all nodes are done decoding the generation. This way the only message needed is the message requesting a new generation.
